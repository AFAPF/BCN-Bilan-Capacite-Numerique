# Arborescence des écrans et parcours

**Statut : spécification fonctionnelle recommandée**
**Principe :** séparer strictement la gestion professionnelle de l’espace de passation du jeune.

## 1. Arborescence

### Écrans hors coffre

1. démarrage ;
2. déverrouillage du coffre ;
3. récupération administrateur ;
4. création initiale du coffre ;
5. erreur de compatibilité ou migration.

### Espace professionnel

1. accueil ;
2. dossiers jeunes ;
3. dossier jeune ;
4. nouvelle passation ;
5. préparation et contrôle matériel ;
6. reprise d’une passation ;
7. bilan et observations ;
8. rapports et exports ;
9. corbeille ;
10. profils et droits ;
11. sauvegarde et restauration ;
12. réglages, contenus et versions ;
13. journal d’audit ;
14. aide, confidentialité et accessibilité.

### Espace de passation

1. accueil du jeune ;
2. vérification du dispositif ;
3. calibration éventuelle ;
4. consigne ;
5. entraînement ;
6. validation de la zone de départ ;
7. item noté ;
8. transition neutre ;
9. pause ;
10. interruption professionnelle ;
11. fin de tâche ;
12. fin de séance.

## 2. Navigation professionnelle

Navigation principale recommandée :

- Accueil ;
- Dossiers ;
- Rapports ;
- Administration, visible uniquement pour l’administrateur ;
- Aide.

L’identité du profil actif et le bouton Verrouiller restent disponibles. Les actions rares sont regroupées sans surcharger l’accueil.

## 3. Accueil professionnel

L’accueil affiche :

- Reprendre une passation ;
- Nouvelle passation ;
- Dossiers récents autorisés ;
- sauvegarde à effectuer ;
- incompatibilité ou mise à jour nécessitant une action ;
- espace de stockage disponible lorsqu’un seuil est atteint.

Il n’affiche pas de classement de jeunes, moyenne générale ou comparaison normative non validée.

## 4. Création d’une passation

Étapes :

1. sélectionner ou créer le dossier nominatif ;
2. vérifier âge et niveau scolaire ;
3. sélectionner les modules et tâches indépendantes ;
4. renseigner matériel, dispositifs et adaptations ;
5. choisir condition standard ou adaptée ;
6. vérifier consentements ou traces d’information exigées par l’organisme ;
7. effectuer les contrôles techniques ;
8. afficher un récapitulatif ;
9. démarrer l’espace jeune.

Le professionnel peut enregistrer et quitter avant le démarrage.

## 5. Contrôles préalables

Le contrôle vérifie :

- compatibilité du navigateur ;
- fonctionnement hors connexion ;
- stockage et intégrité ;
- sauvegarde conforme à la politique ;
- espace disponible ;
- écran et orientation ;
- zoom ;
- calibration physique ;
- clavier et disposition ;
- pointeur ou tactile ;
- son ;
- absence de mise à jour en attente bloquante.

Chaque contrôle donne un résultat : conforme, avertissement documenté ou incompatible.

## 6. Passage à l’espace jeune

Avant de confier l’écran :

- les données personnelles disparaissent ;
- les raccourcis administratifs sont neutralisés ;
- la consigne d’accueil est affichée ;
- le professionnel confirme que le jeune est prêt ;
- le chronomètre de l’item n’est pas démarré.

La sortie de l’espace jeune exige une action professionnelle protégée qui ne peut pas être déclenchée par erreur pendant l’épreuve.

## 7. Déroulement d’une tâche

Séquence standard :

1. consigne écrite et audio lorsque prévue ;
2. item d’entraînement ;
3. éventuel second essai ;
4. réserve enregistrée si la compréhension reste incertaine ;
5. préparation du premier item ;
6. validation du départ ;
7. apparition de la cible ou du contenu et démarrage du temps ;
8. réponse unique ou activité selon l’épreuve ;
9. enregistrement atomique ;
10. transition neutre ;
11. item suivant ;
12. fin de tâche sans résultat affiché au jeune.

Les variantes propres à chaque module priment sur cette séquence.

## 8. Pause

Une pause peut être demandée entre deux items ou imposée après une interruption sûre.

L’écran de pause :

- masque la tâche et les données ;
- n’affiche aucun résultat ;
- indique que le temps est arrêté ;
- demande l’authentification professionnelle pour reprendre si la pause se prolonge ;
- vérifie que matériel, orientation et calibration n’ont pas changé.

## 9. Intervention professionnelle

Pendant un item noté, le professionnel peut utiliser une commande protégée « Interrompre ».

Il choisit ensuite :

- besoin d’aide ;
- incident matériel ;
- problème de compréhension ;
- fatigue ou attention ;
- urgence ou abandon ;
- autre motif avec texte.

L’item est arrêté et traité selon la règle du module. Aucune aide n’est ajoutée silencieusement à un item noté.

## 10. Reprise après fermeture

Le professionnel voit :

- nom et prénom du jeune ;
- séance, module et tâche ;
- dernier événement complet ;
- raison de l’arrêt ;
- matériel et calibration précédents ;
- action recommandée : reprendre, recommencer la tâche ou clôturer partiellement.

BCN ne relance jamais automatiquement un chronomètre.

## 11. Fin de séance

Le professionnel :

1. récupère l’écran ;
2. s’authentifie si nécessaire ;
3. vérifie modules complets, partiels et incompatibles ;
4. complète aides, incidents et observations ;
5. planifie éventuellement une autre séance ;
6. clôture la séance ;
7. effectue la sauvegarde recommandée.

Le jeune ne voit ni score ni formulation interprétative à cet écran.

## 12. Bilan

Le bilan comporte des onglets ou sections stables :

- contexte ;
- conditions de passation ;
- résultats par module ;
- aides et incidents ;
- observations ;
- synthèse ;
- préconisations ;
- versions et limites ;
- historique.

Les mesures objectives, observations professionnelles et interprétations utilisent des présentations distinctes.

## 13. Consultation et modification

Avant clôture, le créateur modifie les champs autorisés.

Après clôture :

- lecture de la version signée ;
- ajout d’un avenant ;
- réouverture par administrateur avec motif ;
- conservation de chaque version ;
- mesures brutes toujours immuables.

## 14. Export

Parcours :

1. choisir PDF individuel, CSV de travail ou jeu d’étude ;
2. conserver le bilan nominatif ; choisir un export d’étude anonymisé uniquement dans le parcours d’étude distinct ;
3. afficher les champs inclus ;
4. signaler les données identifiantes ;
5. choisir protection et destination ;
6. confirmer ;
7. générer ;
8. vérifier l’intégrité ;
9. inscrire l’export au journal.

Un export échoué ne crée pas de trace trompeuse de réussite.

## 15. Suppression

- action ordinaire : placer dans la corbeille ;
- récapitulatif exact avant confirmation ;
- restauration réservée à l’administrateur ;
- suppression définitive avec double confirmation et authentification ;
- aucune mesure sensible affichée dans la fenêtre de confirmation ;
- historique minimal conservé selon les règles juridiques.

## 16. États de chaque écran

Chaque écran est spécifié dans les états :

- initial ;
- chargement ;
- vide ;
- rempli ;
- modification non enregistrée ;
- sauvegarde ;
- erreur récupérable ;
- erreur bloquante ;
- hors connexion ;
- verrouillé ;
- droits insuffisants ;
- incompatible.

Aucune conception d’écran n’est validée si un de ces états pertinent manque.

## 17. Maquettes à produire avant le code

Maquettes non fonctionnelles obligatoires :

1. création et déverrouillage du coffre ;
2. accueil professionnel ;
3. liste et fiche dossier ;
4. assistant de nouvelle passation ;
5. contrôle matériel et calibration ;
6. consigne et entraînement ;
7. item de chaque tâche ;
8. pause et interruption ;
9. reprise après incident ;
10. bilan compact par tâche ;
11. rapport avant export ;
12. administration des profils ;
13. sauvegarde et restauration ;
14. états d’erreur, incompatibilité et verrouillage.

Chaque maquette existe au minimum en largeur ordinateur et tablette. Le téléphone est maquetté uniquement pour les parcours autorisés de consultation ou préparation.

## 18. Critères d’acceptation

- aucune donnée identifiable n’est visible dans l’espace jeune ;
- le jeune ne peut pas atteindre les résultats pendant la passation ;
- une passation ne commence pas si un contrôle indispensable échoue ;
- chaque interruption produit un état explicite ;
- une pause ne compte pas dans le temps actif ;
- une reprise n’utilise pas une calibration devenue invalide ;
- aucune suppression définitive n’est possible par erreur simple ;
- chaque écran possède les états nécessaires ;
- le parcours complet est réalisable au clavier côté professionnel ;
- les droits définis dans la matrice sont respectés dans chaque action.
