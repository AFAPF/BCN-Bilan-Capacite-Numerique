# Stratégie d’essai personnel et d’expérimentation

**Statut : décision du porteur du projet**
**Porteur actuel :** projet personnel.
**Diffusion :** aucune diffusion opérationnelle prévue avant une période d’usage personnel et une décision explicite.

## 1. Positionnement actuel

BCN est conçu à titre personnel par son porteur, qui souhaite l’utiliser comme outil professionnel après une phase de préparation et d’autorisation.

Le dépôt public sert à documenter la conception. Il ne signifie pas que le logiciel est librement réutilisable, validé, disponible ou autorisé dans un cadre professionnel.

Aucune licence n’est attribuée à ce stade. Tous les droits restent réservés. Le choix d’une licence est volontairement reporté jusqu’à ce que la pertinence du logiciel, ses conditions d’usage et le projet de diffusion soient mieux établis.

## 2. Progression retenue

### Étape 1 — Préproduction

Objectif : terminer le cahier des charges avant le code.

Données admises :

- aucune donnée réelle de jeune ;
- exemples entièrement fictifs ;
- aucun nom, identifiant scolaire ou document professionnel réel.

Sortie attendue : validation de la porte d’entrée en production.

### Étape 2 — Développement et essais techniques

Objectif : vérifier le fonctionnement technique de la version initiale.

Données admises :

- données fictives ;
- profils de démonstration ;
- scénarios artificiels ;
- aucun jeune réel.

Cette étape comprend les tests automatiques, les essais manuels, la sécurité, la restauration et la compatibilité des appareils.

### Étape 3 — Essai simulé

Objectif : tester les parcours avec des adultes volontaires ou des collègues jouant des scénarios fictifs.

Conditions :

- aucune donnée d’élève ;
- résultats sans valeur professionnelle ;
- erreurs et incompréhensions consignées ;
- aucune intégration dans un dossier institutionnel.

### Étape 4 — Expérimentation professionnelle limitée

Objectif : utiliser BCN avec de vrais jeunes dans un périmètre restreint.

Conditions préalables obligatoires :

- accord écrit ou formalisé de la structure ;
- identification du responsable du traitement ;
- examen avec le DPO ou référent compétent ;
- inscription du traitement dans le registre de l’organisme lorsque nécessaire ;
- base légale et information des jeunes et représentants définies ;
- appareil autorisé et administré ;
- procédure d’incident et de sauvegarde validée ;
- données minimisées et pseudonymisées ;
- version identifiée comme expérimentale et non étalonnée ;
- possibilité d’arrêter l’expérimentation.

Le fait que l’application soit locale, personnelle ou gratuite ne supprime pas ces exigences.

### Étape 5 — Usage personnel professionnel prolongé

Objectif : évaluer la pertinence pendant plusieurs mois.

Le porteur reste l’unique utilisateur de BCN, sous réserve de l’autorisation de la structure. Il tient un registre d’expérience comprenant :

- version utilisée ;
- nombre de passations ;
- tâches réellement utilisées ;
- incidents et incompatibilités ;
- durées ;
- incompréhensions ;
- adaptations nécessaires ;
- erreurs de calcul ou d’export ;
- retours des jeunes et professionnels ;
- modifications envisagées.

Les retours sont conservés sans données identifiantes dans le dépôt public.

### Étape 6 — Décision de diffusion

Après la période d’usage, trois décisions sont possibles :

1. arrêter le projet ;
2. continuer comme outil personnel autorisé ;
3. préparer une diffusion à d’autres professionnels.

Une diffusion nécessite une nouvelle revue portant notamment sur :

- licence du code et des contenus ;
- titulaire des droits ;
- gouvernance ;
- documentation et formation ;
- support et maintenance ;
- sécurité et mises à jour ;
- responsabilité et conditions d’utilisation ;
- accessibilité ;
- validation scientifique ;
- cadre de traitement des données dans chaque structure.

## 3. Séparation des responsabilités

### Conception personnelle

Le porteur décide du produit, de son code, de ses contenus originaux et de sa feuille de route, sous réserve des droits des éventuels contributeurs.

### Usage professionnel

Lorsque BCN traite les données de jeunes dans le cadre du travail, l’usage doit relever d’un cadre autorisé par l’organisme. L’organisme qui décide des finalités et des moyens essentiels doit identifier son rôle de responsable du traitement.

Le porteur du projet ne doit pas décider seul que son statut de créateur lui permet d’utiliser des données professionnelles dans l’application.

## 4. Limites de communication

Avant validation :

- ne pas présenter BCN comme outil du PAS ou de l’employeur ;
- ne pas utiliser de logo institutionnel sans autorisation ;
- ne pas parler de test validé, normé ou étalonné ;
- ne pas publier de résultat individuel ;
- ne pas publier de capture contenant une donnée réelle ;
- ne pas proposer le téléchargement opérationnel à des tiers ;
- indiquer « projet personnel expérimental, non validé ».

## 5. Données de travail et dépôt public

Ne doivent jamais entrer dans GitHub :

- identité d’un jeune ;
- réponse brute réelle ;
- observation professionnelle réelle ;
- rapport individuel ;
- export CSV réel ;
- sauvegarde de l’application ;
- secret, clé ou code d’accès ;
- document interne de la structure non publiable.

Les anomalies sont reproduites avec des données fictives avant d’être documentées.

## 6. Critères pour passer à une expérimentation réelle

Tous les critères suivants doivent être remplis :

- porte d’entrée en production validée ;
- version candidate techniquement qualifiée ;
- accord de la structure obtenu ;
- responsabilités RGPD identifiées ;
- information adaptée préparée ;
- sécurité et sauvegarde testées ;
- procédure de retrait et suppression disponible ;
- rapport clairement expérimental ;
- aucune norme non validée ;
- journal d’incidents prêt ;
- décision de démarrage consignée.

## 7. Critères après plusieurs mois d’usage

La pertinence est examinée sur :

- utilité réelle pour l’observation ;
- compréhension par les jeunes ;
- durée acceptable ;
- stabilité ;
- qualité des mesures ;
- capacité à expliquer les résultats ;
- nombre et gravité des incidents ;
- compatibilité matérielle ;
- charge de travail professionnelle ;
- respect de la confidentialité ;
- bénéfice supérieur aux contraintes.

La diffusion n’est envisagée que si les résultats sont suffisamment favorables et si les risques restant ouverts disposent d’un plan de traitement.

## 8. Décisions différées

Les décisions suivantes sont volontairement reportées :

- licence libre, propriétaire ou double ;
- nom de l’éditeur diffusé ;
- structure juridique éventuelle ;
- ouverture aux contributions ;
- hébergement ou synchronisation ;
- tarification éventuelle ;
- support aux utilisateurs ;
- publication dans des catalogues ou magasins d’applications.
